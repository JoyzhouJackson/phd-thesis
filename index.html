我的研究

上海交通大学 × 米兰理工大学

01 · 背景与痛点

柔性自动化解决了“能不能生产”，
却没有自动解决“怎样高效生产”。

托盘自动化系统示例 · 视频来自用户提供的 Fastems 参考资料

1

订单变化快

多品种、小批量和短交期，让固定生产计划很快失效。

2

资源必须共享

多个工件竞争机器、夹具托盘、设置站和物料托盘。

3

局部最优会制造拥堵

眼前更快的选择，可能延长资源占用并拖慢整个订单。

真正的瓶颈，是如何把系统的物理柔性转化为生产效率。

02 · 研究对象与难点

柔性托盘自动化系统
Pallet Automation System

机器决定加工时间
×
夹具托盘随工件等待与加工
×
设置站承担装载与卸载
×
物料托盘影响存储与释放
难点一

约束多

兼容选择、同步占用、先后衔接、等待与释放必须同时满足。

难点二

耦合强

机器选择会改变夹具占用；夹具选择也会改变机器等待。

难点三

规模增长快

资源和工件增加后，可行组合与决策空间迅速扩大。

03 · 研究现状

现有方法能优化生产，
但真正的多资源联合学习仍然少见。

研究方向主要决策RL 的作用
标准柔性作业车间工序 + 机器直接学习分配
多资源调度机器 + 运输 / 工人等多用于选择规则、算子或参数
已有 PAS 学习方法主要学习夹具托盘选择工序与机器仍由固定规则决定
本研究工序 + 夹具托盘 + 机器端到端联合决策

根据第五篇论文 “RL applications in FJSP and MRFJSP” 文献表归纳。

研究缺口从“让 RL 辅助算法”，走向“让 RL 直接完成多资源调度”。

05 · AI 研究重点

先让智能体学会调度，
再让它发现自己看不见什么。

强化学习

一次动作，完成三类联合选择

智能体直接选择一个可行的“工序—夹具托盘—机器”组合，并通过仿真回报学习局部效率与长期拥堵之间的权衡。

工序×夹具托盘×机器→联合动作

LLM Agent

把“为什么选错”变成一个可检验的假设

LLM 不直接生成最终调度策略。它阅读反事实错例，解释可能缺失的上下文，再把想法编译为可计算特征与实验配置。

LLM 提建议→实验做裁判
1

寻找反例

定位长期结果明显更差的决策。

→
2

诊断缺失信息

提出可计算、无信息泄漏的特征。

→
3

重新训练验证

不通过预设门槛就拒绝晋级。

新特征即使解决了原来的错误，只要整体性能变差，就不把它包装成成功。
