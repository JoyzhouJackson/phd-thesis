01 · 背景与痛点

柔性设备解决了“能不能生产”

托盘自动化系统示例 · 视频来自用户提供的 Fastems 参考资料

1

宏观背景

随着产品定制化程度提高和生命周期缩短，生产模式正从少品种大批量转向多品种小批量。企业因此面临柔性自动化升级难题，而托盘自动化系统（PAS）是重要解决方案之一。

2

行业升级意愿强

Fastems 对中国托盘自动化应用的调查显示，78% 的受访企业计划在一至三年内升级 PAS。更高的产品多样性和更短的交付窗口，使 PAS 的高效运行成为日益重要的生产管理问题。

3

PAS 把柔性设备连成系统

PAS 通过标准化托盘整合异构机床、共享设置站、自动搬运与存储及中央控制，减少人工搬运和非加工时间，提高设备利用率与无人化生产能力，并支持模块化扩容和重构。

真正的瓶颈，是如何把系统的物理柔性转化为生产效率。

难点一

约束多

兼容选择、同步占用、先后衔接、等待与释放必须同时满足。

难点二

耦合强

机器选择会改变夹具占用；夹具选择也会改变机器等待。

难点三

规模增长快

资源和工件增加后，可行组合与决策空间迅速扩大。

05 · AI 研究重点

先让智能体学会端到端联合决策，
再让 LLM 用反例推动策略持续改进。

强化学习 · End-to-End Q-Learning

一个动作，同时决定工序、夹具托盘和机器

候选筛选与三层离散化共同控制状态—动作规模，使相似调度情境能够共享经验；核心是在保留关键决策差异与避免 Q 表过度稀疏之间取得平衡。

工序×夹具托盘×机器→联合动作
01 · STATE

候选动作的状态表示

用设置时间、加工时间、工序等待、机器等待、剩余工作量和工序柔性六个离散特征描述每个候选动作。

端到端联合动作

先生成所有可行的工序—夹具托盘—机器组合，再保留兼顾设置、加工和等待偏好的代表候选，由智能体完成最终选择。

过程反馈 + 完工反馈

从当前结果修正长期价值

用即时回报与下一决策点的最佳估计共同更新 Q 值，使一次联合选择能够学习其对后续调度的影响。

结果 · 100 个测试案例

在覆盖完整测试集的比较方法中，智能体的平均 makespan 均更低

总体比较覆盖 GA、TS、SA、规则组合与上一代智能体。Gurobi 仅评估最小的 15 个案例，因此不纳入这项完整测试集结论。

极端测试暴露的边界

在装卸时间占主导的极端场景中，三层离散化会把差异明显的设置时间映射到同一类别，造成信息损失；智能体平均比 Rule 2 差 3.39%。这说明常规测试上的优势并不等于状态表示已经覆盖所有分布变化。

LLM Agent · Counterexample-driven Learning

LLM 不替代调度智能体，而是帮助它发现表示缺陷

Agent 从反事实决策中寻找“当前策略选了什么、换一个动作会怎样”，把错误转化为可证伪的特征假设，再由冻结的实验协议决定淘汰、晋级或结束。

LLM 生成假设→程序执行实验→证据决定去留
GOAL

目标

减少有害反例，同时不牺牲独立测试集的整体调度性能。

PERCEPTION

感知

读取已选动作、可行替代、最终 makespan、特征差异与状态键冲突。

REASONING

推理

诊断缺失信息，并提出一次只改变一个表示因素的可检验假设。

MEMORY

记忆

保存每轮假设、配置、结果与失败原因，避免重复无效方向。

TOOLS

工具

调用冻结仿真器、训练器、反例挖掘、状态混叠分析和验证程序。

ACTION

行动

把假设编译为新特征与隔离配置，启动实验并按门槛晋级或淘汰。

什么是反例？

从完全相同的决策前状态出发，分别执行当前所选动作和每个可行替代动作，再用同一冻结贪心策略完成后续调度；若所选动作造成的最终 makespan 比最佳替代高至少 1%，则记为有害反例。若两者还共享同一个离散状态键，则构成最强的“信息丢失”证据。

第一层 · 粗略筛选

低成本淘汰弱假设

  • Seed A × 500 epochs
  • 验证集最佳五检查点移动平均达到性能底线
  • 反例率或同键反例数必须改善
  • 仅弱改善时，再用 Seed B 复核
通过才进入 →
第二层 · 精细筛选

完整科学确认

  • A / B / C 三个固定种子 × 2000 epochs
  • 五个发现集案例逐动作反例挖掘
  • 冻结的 100 案例独立测试
  • 记录复杂度、状态混叠与总体性能
改进方向

优先尝试相对化表示、替换弱信息特征、补充资源耦合上下文，并控制状态维度与 Q 表稀疏性。

什么样算好

有害反例减少、严格同键反例降为 0，且冻结独立测试的宏观性能不低于无选择器基准。

何时结束闭环

候选通过完整精筛即接受；若预先约定的迭代预算耗尽仍无候选通过，则以“尚未解决的局限”结束，而不是继续追逐正结果。

06 · 结论

四个研究点对应一条完整路线：
描述、求解、学习、改进。

描述建立多资源耦合约束的 PAS 调度模型
→
求解用元启发式高效搜索复杂解空间
→
学习用强化学习实现端到端联合决策
→
改进用 LLM Agent 构建反例驱动的自学习闭环

最终目标：形成更稳定、泛化性更强、具备自学习能力、动态响应快且可跨系统迁移的调度模型，适应不同的制造场景。
